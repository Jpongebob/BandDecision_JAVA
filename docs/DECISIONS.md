# 설계 변경과 이유

## D31. GUI 전용·수동 백업/복원 제거 (2026-11-18, H35)

사용자 요청으로 ConsoleUI·DateParser·BackupService를 제거했다. 입력 경로를 GUI로 통일하여 유지 코드를 줄이고 핵심 합주 결정에 집중한다. 두 실행 스크립트는 계속 사용 가능하며 모두 GUI를 연다. 콘솔 문자 날짜 입력은 폐기하고 달력 하루/기간/전체 선택은 유지한다.

수동 파일 내보내기·불러오기만 제거한다. 자동 저장·시작 시 읽기·지금 저장·응답 한 단계 되돌리기는 유지한다. 구버전 파일 변환 시 원본 보관은 호환 보호이므로 유지한다. 사용자 파일은 삭제하지 않았다. 장점은 흐름·코드 단순화, 단점은 화면 없는 환경 사용과 UI 백업 파일 선택 불가다. D29 수동 백업 정책은 폐기됐다.

기준일 2026-11-11. 현재 채택 여부를 명시하며, 초기 SPEC을 수정 이력 없이 현재 정책으로 취급하지 않는다.

최신 일정 정책은 **D14**이다. D09/D12의 후보 사전 등록·전체 응답 차단 및 D13의 후보 등록 관련 설명은 변경 당시의 이력이며 D14로 대체됐다. D13의 두 달 표시 제한은 유지한다.

## D09의 상세 정책과 선택 이유

- 후보를 오늘 포함 60일 안에서 등록한다. 5~10개는 입력 부담을 줄이기 위한 권장 수이며 한 개도 가능하고 상한을 강제하지 않는다.
- 후보를 하나 추가하면 6명 모두 `미응답`이다. 빈칸을 참석 가능이나 불참으로 간주하지 않는다.
- 추천 전제는 **유효한 모든 후보에 6명 전원이 응답**하는 것이다. 일부 후보만 응답 완료됐더라도 전체 응답 전에는 추천/신규 확정을 하지 않는다.
- 과거가 된 후보는 기록은 남기되 현재 추천의 응답 완료 판단에서 제외한다.
- 전원 가능 날짜를 먼저 보여주며, 없으면 가능 인원이 많은 후보부터 보여준다. 같은 인원이면 빠른 날짜다.
- 1~5명 가능 후보도 추천할 수 있지만 수동 확정 전 불참 파트·사유와 별도 경고를 표시한다. 임의로 4명 이상 같은 하한을 만들지 않았다.
- 불가 사유는 현재 선택 사항이다. 생략 시 `불가 응답`으로 기록한다. 곡의 **반대 사유는 계속 필수**이므로 일정 응답과 곡 투표를 구분한다.
- 이 선택은 사용자 사용성 피드백에 따른 설계 변경이다. 응답 완료 전에는 후보가 늘수록 대기할 수 있다는 단점이 있으며, 해당 동작을 오류로 기록하지 않는다.

## D11. 후보곡 수정·삭제 및 ID 보존 (2026-11-11, 채택)

초기 명세의 후보곡 관리 범위를 사용자 요청에 따라 확장했다. 제목·아티스트·6파트 난이도를 모두 검증한 뒤 함께 수정하고 기존 투표·반대 사유는 유지한다. 난이도 변경은 현재 부담 점수에 반영한다. 사용자가 정보를 바꾼 뒤 필요하면 재투표할 수 있다. 삭제 확인 후에는 후보곡과 그 투표·사유를 제거하지만 확정 당시 스냅샷은 유지한다. 삭제는 되돌리기를 제공하지 않으므로 GUI·콘솔에서 확인을 받는다.

종전의 배열 길이 기반 ID는 중간 삭제 시 충돌할 수 있어 별도 증가 값을 사용한다. 삭제 후 다른 곡의 ID를 바꾸거나 재사용하지 않고 `songs.nextId`를 저장한다. 해당 항목이 없는 기존 파일은 최대 저장 ID 다음부터 복원하므로 파일 버전 v2를 유지한다. 투표 콤보박스도 ID로 선택을 추적하고 선택한 곡이 삭제되면 선택을 해제하여 다른 곡에 잘못 투표하지 않게 한다. 번호가 연속하지 않을 수 있고 저장 항목이 하나 늘지만 기존 데이터·투표 대상의 일관성을 유지한다. 이미 삭제된 과거 ID는 기존 파일에 정보가 없으면 추정할 수 없다.

## D12. 월별 달력과 선택 날짜 상세 응답 (2026-11-11, 채택)

사용자 요청에 따라 후보×멤버 전체 표를 왼쪽 달력·오른쪽 6명 응답표로 대체했다. 날짜와 요일, 가능한 후보를 한눈에 보고 선택한 날짜의 사유까지 편집하려는 목적이다. `ScheduleCalendarPanel`은 월 이동·날짜 선택·상태 표시를 담당하고 기존 서비스·추천 계산·저장을 재사용한다. 달력 칸은 전원 명시적 가능일 때만 `합주 가능`, 미응답이 있으면 대기 인원, 나머지는 가능 인원을 표시한다. 미등록 날짜·기간 밖 후보는 합주 가능으로 계산하지 않는다. 이 표시는 최종 확정이 아니며 전체 후보 응답 완료 정책은 유지한다.

월을 이동해도 선택한 응답 대상은 유지하며 날짜 클릭 시에만 바꾼다. 미등록 날짜는 명시적으로 추가해야 응답할 수 있다. 단일/쉼표/공백/기간 후보 입력은 유지하지만 여러 날짜 행의 동시 응답은 단일 날짜 상세 편집으로 대체하여 화면을 단순화했다. 날짜 간 멤버 비교에는 이전 표보다 클릭이 필요하다는 단점이 있다. 저장 형식·기존 후보·응답·확정 기록은 바꾸지 않는다. 불가 사유를 비우면 선택 사항 정책에 맞춰 기본 문구로 저장한다.

## D13. 달력은 이번 달·다음 달로 제한 (2026-11-11, 채택)

사용자 요청으로 이전 달 버튼을 없애고 고정된 이번 달/다음 달 선택으로 변경했다. 반복 클릭이나 후보 입력 후에도 달력은 이 두 달 안에 머문다. 월 선택은 응답 대상 날짜를 바꾸지 않으며 오늘 버튼은 오늘을 선택한다. 달력 표시 범위와 기존 60일 후보 정책을 분리했다. 60일이 세 번째 달에 걸치거나 과거 후보가 남은 경우 기존 데이터가 접근 불가가 되지 않도록 오른쪽 후보 선택 목록을 조건부로 표시한다. 목록에서 해당 날짜의 응답 편집은 계속 가능하고 저장 형식·추천·콘솔은 유지한다. 두 달만 보여 화면은 단순해지지만 범위 밖 후보는 선택 목록을 이용해야 한다.

## D14. 후보 사전 등록 제거·날짜별 추천 (2026-11-11, 채택)

모든 날짜에서 바로 응답하고 선택 날짜 후보 추가를 없애 달라는 요청을 반영했다. 후보 추가/삭제와 날짜 입력란을 GUI에서 제거하고, 날짜 클릭 즉시 6행을 표시한다. 미기록 날짜의 기본값은 전원 미응답이며 첫 응답 때 저장 행을 만든다. 조회만으로 기록을 채우지 않는다. 콘솔도 후보 등록 없이 날짜를 입력하여 응답한다. GUI는 과거 날짜를 포함한 표시 날짜의 응답 편집을 지원하며 추천·신규 확정은 기존 오늘~59일 뒤 범위를 유지한다.

모든 날짜를 응답 대상으로 삼으면 ‘모든 후보의 전원 응답’ 조건은 추천을 사실상 막으므로 D09/D12의 전체 차단 정책을 대체했다. **날짜별로 6명 응답이 완료된 날만 추천**하고 미응답 날짜는 그 날짜만 제외한다. 선택 날짜만 전원 응답했는지 최종 확정 직전에 재검증하며 부분 참석 동의·곡 자격·스냅샷 정책은 유지한다. 다른 날까지 완료를 강제하지 않는 대신 완료 전 날짜는 비교에서 빠진다는 한계가 있다.

저장 형식 v2와 `candidate.*` 키는 기존 파일 호환을 위해 유지하며 이제 이 행들은 날짜 응답 기록이다. 서비스의 구 등록/삭제 메소드는 복원·기존 검사 지원용으로 남지만 사용자 후보 관리 절차는 없다. 날짜를 삭제하지 않고 응답을 미응답으로 수정한다. 기존 응답·곡·확정 기록은 유지한다. D13의 두 달 표시와 범위 밖 기존 기록 선택도 유지한다.

## D15. 클릭으로 날짜 다중 선택 후 응답 적용 (2026-11-11, 채택)

사용자 예시의 하루씩/기간으로/월 전체 선택을 도입했다. 하루씩은 클릭마다 추가·해제하며 기간은 두 번의 클릭으로 양끝 포함 날짜를 선택한다. 종료일을 먼저 클릭하거나 월을 이동하는 기간도 허용한다. 표시 월 전체 선택은 과거를 포함한 그 달의 모든 날짜로 정의한다. 모드 변경 시 선택과 미완성 기간을 초기화하고 월 이동은 선택을 유지한다. 종료일 선택 전이나 빈 선택에서는 적용을 막는다. 선택 자체는 저장 데이터를 변경하지 않는다.

적용은 별도 멤버·가능/불가/미응답 버튼으로 명시하며 표 직접 편집은 현재 표시 날짜 한 개만 바꾼다. 범위를 잘못 적용하는 일을 줄이기 위해 선택 개수와 표 편집 대상 날짜를 함께 안내한다. 불가 사유 공란은 날짜별 기존 사유를 유지하며 신규 불가에는 기본 문구를 쓴다. `AttendanceService.respondMany()`는 멤버·응답 값·모든 날짜를 검증한 뒤 반영하고 UI는 한 번 저장한다. 추천·확정·파일 형식은 D14를 유지한다. 별도 GUI 기간 문자열 입력은 없으며 콘솔의 기존 날짜 입력 기능은 유지한다. 다중 선택에 따른 조작 영역이 늘어 기본 90%에서 6명 응답을 함께 보이도록 표와 여백을 조정했다.

## D16. 개인 응답 색상 유지·완료 여부만 표시 (2026-11-11, 채택)

선택한 날짜를 계속 다른 색으로 보여 주고 응답 일수는 없애 달라는 요청을 반영했다. 편집할 날짜의 일시적인 체크와 저장된 응답을 구분한다. 달력 배경은 선택 멤버의 가능 파랑·불가 빨강이며, 6명 전원 가능은 초록을 우선한다. 미응답은 기본 배경이다. 멤버 변경·선택 해제·월 이동 때 저장 응답으로 다시 그리므로 색상이 남고 재실행 후에도 해당 멤버를 선택하면 복원된다. 선택 멤버 자체의 재실행 설정 저장은 추가하지 않았다.

멤버 표는 응답 완료/미응답, 상단 요약은 전체 응답 완료/응답 미완료로 단순화했다. 기존 `isSubmitted()/allSubmitted()`를 사용해 응답 기록이 있는 유효 날짜 전체에 대한 명시적 응답 유무만 판단한다. 아무 기록도 없으면 미완료이며 기록이 없는 달력 날짜를 자동으로 가능 처리하거나 모두 응답해야 한다고 강제하지 않는다. 이 요약은 추천 자격을 막는 조건이 아니고 D14의 날짜별 완료 정책은 유지한다. 선택 개수는 적용 범위를 확인하기 위해 계속 표시한다. 저장 형식과 추천·확정 정책은 변경하지 않았다.

현재 선택한 미응답 날짜는 연보라로 구분하며 선택을 해제하면 기본 배경으로 돌아간다. 이미 저장한 가능/불가의 배경은 선택 체크 여부와 관계없이 유지한다.

## D17. 지난 날짜 비활성화·월 전체 선택 전환 (2026-11-11, 채택)

지난 날짜를 비활성화하고 월 전체 선택을 재클릭하면 해제해 달라는 요청이다. 지난 날짜 칸은 회색·비활성, 기존 응답표는 읽기 전용이며 직접 편집과 다중 적용도 막는다. 기존 기록은 삭제하지 않는다. 월 전체는 오늘부터 표시 월 말일까지의 날짜이며 현재 선택과 같으면 비운다. D15의 과거 포함 전체 선택과 D14의 과거 응답 편집 설명을 대체한다. 월이 바뀌거나 날짜가 지나면 선택에서 지난 날짜를 제외한다. 추천의 오늘~59일 뒤 범위는 유지한다.

## D18. 확정 계획 최대 5개·명시적 수정/삭제·v3 (2026-11-11, 채택)

기존 최근 계획 1건 덮어쓰기를 배열 목록으로 바꾸고 `ConfirmedPlan`의 고유 ID와 불변 스냅샷을 보관한다. 신규 확정은 추가하고 최대 5개에서 거부하며 자동으로 옛 계획을 지우지 않는다. 수정은 같은 ID의 내용만 교체하고 5개가 찬 상태에서도 가능하다. 삭제 후 다른 계획의 ID·순서를 바꾸거나 ID를 재사용하지 않는다. 같은 날짜의 별도 계획도 허용한다. 조회는 목록 선택으로 대상을 명시한다. D08의 스냅샷 불변성은 유지하지만 ‘최근 1건만 보관’은 대체한다.

GUI 수정은 현재 추천 화면으로 이동하고 현재 유효한 기존 날짜·곡을 미리 선택한다. 수정 확정 전에 선택 날짜 전원 응답·곡 자격·최신 데이터 일치·부분 참석 동의를 다시 검사한다. 과거/추천 제외 날짜·삭제/자격 상실 곡은 현재 유효한 항목으로 다시 선택해야 한다. 취소·실패는 원본을 보존한다. 삭제는 확인 후 계획만 제거하며 응답·곡·다른 스냅샷을 유지한다. 콘솔 메뉴 10에서도 같은 서비스를 사용한다.

파일 v3에 ID·목록·다음 ID를 저장한다. v1/v2는 기존 단일 계획을 ID 1인 목록 1개로 복원하고, 최초 저장 전 버전별 `.v1.bak`/`.v2.bak`을 만든다. v1의 옛 불가능 일정에서 가능 여부를 추정하지 않는 기존 정책은 유지한다. 5개 초과·잘못된 ID·손상 형식은 읽기를 거부하며 사용자 파일을 덮어쓰지 않는다. 이전 프로그램은 v3를 읽지 못한다는 호환 한계가 있다.

## D19. 일반 클릭은 하루만 선택 (2026-11-11, 채택)

클릭할 때마다 날짜를 누적/해제하는 조작이 불편하다는 사용자 요청으로 D15의 비연속 다중 선택을 제거했다. `하루 선택`에서 클릭은 해당 날짜 하나로 교체하며 같은 날짜를 다시 눌러도 유지한다. 여러 날짜는 기간으로/표시 월 전체만 사용한다. 범위 선택·전체 선택 전환·지난 날짜 비활성·저장 응답 색상·적용 버튼과 계획 관리는 유지한다. 입력 중 오선택을 줄이는 대신 서로 떨어진 여러 날짜를 한 번에 선택하는 기능은 제공하지 않는다. 선택 자체는 데이터와 저장 파일을 바꾸지 않는다.

## D20. 미사용 코드와 중복 화면 정리 (2026-11-11, 채택)

사용자가 불필요한 코드·기능 정리를 요청했다. 호출이 없는 화면 보조 함수·가져오기, 삭제된 정책의 후보 사전 등록 API와 검사, 다중 계획 도입 후 검사에서만 쓰던 최근 단일 계획 조회 API를 제거했다. 검사도 목록 ID로 계획을 조회하도록 바꿨다. 날짜 생성은 첫 응답 때 내부 함수로 처리하고 샘플도 실제 응답 경로를 사용한다. 날짜 기록 조회 이름은 getDates()/activeDates()로 정리한다. 검사 데이터 정리용 삭제 함수는 패키지 내부에만 둔다.

GUI의 파트별 난이도 저장 줄은 곡 수정창과 중복되어 제거하고 제목·아티스트·6파트 난이도를 하나의 수정창으로 통합했다. 콘솔의 파트별 수정은 입력 편의를 위해 유지한다. 전체 투표 결과는 모달 조회 창을 열 때 생성하면 충분하므로 상시 보관·매번 새로 계산하던 표 상태를 제거했다. 옛 불가능 일정 제출용 ‘없음’ 파싱은 현재 입력 경로에서 의미가 없어 제거했다. 원본 없는 오래된 class 3개는 생성물 폴더에서 삭제했다.

v1/v2/v3 읽기·원본 백업과 저장 파일의 candidate.* 키는 기존 데이터 호환에 필요하므로 유지한다. 과거 개발 문서·실제 검사 증거도 보존한다. 현재 기능의 정책을 줄이는 작업이 아니라 중복 진입점과 폐기된 정책 구현을 정리한 것이다. 후보 등록 전용 검사 2개가 사라져 현재 검사 수는 237개이며 이전 수에 합산하지 않는다.

## D21. SCHEDULE은 선택 멤버의 완료 상태 (2026-11-11, 채택)

사용자가 자신의 날짜를 모두 가능으로 입력했으나 SCHEDULE은 미완료라고 보고했다. 읽기 전용으로 저장 상태와 코드를 대조해 개인 응답 완료와 다른 멤버 미응답이 함께 있는 상황, 기존 카드가 allSubmitted()로 6명 전체를 판단하는 상황을 확인했다. D16의 상단 전체 완료 표시는 개인 입력 화면에서 의미가 모호하므로 선택 멤버의 isSubmitted()와 이름을 표시하도록 대체한다.

달력 멤버 선택 콜백은 SCHEDULE 상태/대상과 요약만 갱신하며 저장하지 않는다. 실제 응답 변경은 기존 저장 경로를 유지한다. 멤버 표는 각자의 완료 여부를 유지하고 날짜 추천·신규 확정은 그 날짜 6명 응답 완료 조건을 유지한다. 다른 사람의 미응답을 가능으로 바꾸거나 기존 데이터를 초기화하지 않는다. 완료 범위는 기록이 있는 유효 날짜 전체라는 기존 규칙이다.

## D22. 화면 전환 전 셀 편집 확정과 파일 문자 오류 계약 (2026-11-11, 채택)

추가 오류 점검에서 멤버 변경에 따른 달력 행 갱신이 편집 중 사유를 버리는 것을 재현했다. refresh 전에 finishEditing을 호출하고 모델 변경의 갱신 콜백 전에 편집기를 제거해 stopCellEditing 재진입을 피한다. 날짜 이동은 원래 날짜에 저장한 뒤 이동하며 탭 변경·창 종료도 입력을 확정한다. 기존 자동 저장 정책을 유지한다. D21의 ‘멤버 변경은 저장하지 않음’은 미확정 셀 편집이 없는 경우이며, 이미 입력 중이던 값은 소실하지 않도록 먼저 저장한다. 전환 자체가 새 응답을 만드는 것은 아니다.

Properties.load의 문자 이스케이프 오류는 IllegalArgumentException이므로 save의 IOException 안내에서 빠졌다. 파일 읽기를 공통 함수로 모아 IOException으로 변환하고 원본 교체 전에 중단한다. 데이터 형식 v3·호환·백업·추천 규칙 변경은 없다. 동시 저장 충돌 방지나 권한/디스크 부족 검증을 추가한 것은 아니다.

## 후속 설계 보완

### D23. 달력·응답 완료·추천 범위 통일 (2026-11-12, 채택)

사용자가 부족한 점을 모두 보완하도록 요청했다. 기존 달력은 두 달, 추천은 60일이고 개인 완료는 기록이 있는 날만 검사해 기준이 달랐다. `ScheduleWindow`가 오늘부터 다음 달 말일까지를 정의하고 GUI 응답·개인 완료·추천·확정·콘솔 날짜 입력이 공유한다. 개인은 기간 모든 날짜에 가능/불가로 답해야 완료다. 미기록일도 미응답이며 다른 멤버가 새 기록을 만들어도 완료 기준은 바뀌지 않는다. 기간은 날짜/월이 바뀌면 자연히 이동한다. 표시 이름 옆에 실제 기간을 보여주고 월 전체 적용을 안내한다.

일부 날짜만 응답한 기존 사용자는 미완료로 표시될 수 있으나 데이터 소실이 아니다. 기존 응답·확정 스냅샷·v3 형식은 유지하며 범위 밖 날짜는 읽기 전용으로 조회한다. 날짜별 추천은 개인 전체 완료와 독립적이므로 다른 날 미응답이 완료 날짜 추천을 막지 않는다. 월초/월말/연말/윤년 경계 검사로 옛 60일 검사를 대체한다.

### D24. 마지막 일정 응답 한 단계 되돌리기 (2026-11-12, 채택)

기간·월 전체 오적용을 쉽게 복구하도록 `AttendanceService.Snapshot`이 날짜·응답·사유를 깊게 복사한다. GUI는 성공한 실제 변경 직전 상태 하나만 보관하고 되돌린 후 자동 저장한다. 표 직접 편집도 대상이며 같은 값 적용은 이력을 덮지 않는다. 새로 생성한 날짜 기록까지 복원한다. 곡·투표·실력·계획은 복원 대상에 포함하지 않아 해당 변경은 유지한다. 재실행 시 이력을 보존하지 않고 여러 단계 되돌리기/다시 실행은 제공하지 않는다. 기존 파일 형식은 바꾸지 않는다.

### D25. 월 이동과 화면 구조 정돈 (2026-11-12, 채택)

사용자가 12월에서도 다음 달 버튼이 활성화되고 11월 복귀 버튼 이름이 이번 달인 점을 지적했다. 절대 월 선택을 이전 달/다음 달의 상대 이동으로 바꾸고 첫/마지막 달에서 각각 비활성화한다. 두 달 제한은 유지한다. ‘이 달 전체’로 현재 보이는 월 전체임을 명시한다. 달 이동은 선택 기간과 저장 응답을 바꾸지 않는다.

상단은 일정 응답·후보곡·확정 합주의 세 카드로 줄이고 중복 문구를 제거했다. 달력은 월 이동→선택 방식→날짜 순서, 응답 패널은 날짜/상태→표→멤버/사유→적용 순서다. 되돌리기는 보조 동작으로 분리한다. 작은 창/큰 글자에서는 페이지 전체와 탭을 스크롤한다. 날짜 상태 문구도 배율에 따라 확대한다. 기본 90%는 유지하며 매번 배율을 저장하는 기능은 추가하지 않았다.

## D26. 사용자가 고른 파란 캘린더 디자인 (2026-11-12, 채택)

H29의 정돈으로는 사용자가 원한 시각적 변화가 충분하지 않았다. 스타일을 확인하고 흰 배경·파란 포인트·둥근 날짜 카드라는 사용자의 선택을 반영했다. `UiTheme`의 팔레트·버튼·카드·탭·표 선택을 통일하고 달력 날짜는 전용 버튼 UI로 직접 그린다. 숫자·응답·모서리 체크를 분리해 HTML의 좁은 줄 간격을 피한다. 원래 JButton을 유지해 이벤트·키보드·접근성 이름은 계속 사용하며 선택/오늘 포커스/응답 색상은 별도 상태다.

기본 시작 탭은 달력으로 바꿨다. 사유 칸은 불가인 경우만 내용을 표시해 미응답 중복 배지를 없앴다. 실제 저장된 응답·사유는 변경하지 않는다. 폰트 기본 90%와 확장 스크롤, 일정 기간·추천·투표·확정 정책, v3 파일 호환은 유지한다. 화면 미관의 만족도는 사용자 검토 대상이며 자동 검사 통과를 디자인 선호 검증으로 해석하지 않는다.

## D27. 사용자의 작업 중심으로 전체 화면 통합 (2026-11-12, 채택)

사용자가 사용자 친화적인 전면 개편 제안을 실행하도록 요청했다. 기능별 6탭을 `WorkspaceView`의 일정/곡·투표/합주 계획 세 작업과 별도 밴드 설정으로 바꿨다. 상단 멤버 선택기 하나를 일정 응답·색상·완료 표시와 투표가 공유하며, 투표표에서 다른 멤버를 고를 때도 같은 대상을 표시한다. 외부 선택기를 받지 않는 독립 달력은 자체 선택기를 계속 제공한다.

곡 목록은 ID/제목/아티스트만 보여주고 선택 곡의 6파트 난이도·투표를 오른쪽으로 옮겼다. 독립 투표 곡 드롭다운을 없애 목록과 투표의 대상이 달라질 가능성을 줄였다. 새 곡은 등록 후 자동 선택하며, 수정/앞 곡 삭제 후에는 ID로 선택을 유지한다. 선택 곡 삭제 시 다른 곡으로 자동 투표하지 않고 선택/투표를 비운다. 반대 사유와 전원 투표·추천 자격 정책은 유지한다.

계획 목록·추천/작성·수정은 같은 메뉴 안의 CardLayout으로 전환한다. 새 계획 시작은 선택을 초기화하지만 데이터 변경 없는 일반 메뉴 왕복은 선택을 보존한다. 화면 전환 전에 편집 중인 일정 사유를 확정하는 기존 보호는 유지한다. 계획 용량 5개·수정 재검증·확정 스냅샷·v3 저장은 변경하지 않는다.

중복 요약 카드와 탭 UI/불필요한 탭 스타일을 제거하고 화면별 제목/안내·입력 멤버/응답 상태를 고정했다. 빈 계획과 선택 곡 없음 상태에는 다음 동작을 안내한다. 공개 UI 진입점과 공유 선택기는 Swing 컴포넌트 검사로 연결을 확인하되 네이티브 전체 조작/사용자 만족도 완료로 해석하지 않는다.

## D28. 전체 갱신 재진입 순서와 날짜 전개 상한 (2026-11-12, 채택)

추가 테스트에서 일정 사유 편집 중 전체 갱신을 호출하면 저장 콜백이 갱신을 중첩 호출하고, 안쪽 finally가 refreshing을 false로 돌려 바깥쪽 곡 표 갱신에서 선택 이벤트가 실행되는 문제를 재현했다. DesktopUI.refresh의 플래그를 켜기 전에 편집을 확정한다. 기존 콜백/자동 저장과 선택 ID 보존을 유지하면서 중첩 호출의 상태 간섭을 피한다.

콘솔의 날짜 범위는 실제 허용 기간 검사 전에 모두 펼치고 있었다. 기간 밖 거절은 유지하되 DateParser의 고유 날짜 전개 상한을 62개(연속 두 달의 최대 일수)로 둔다. 중복은 상한에 중복 계산하지 않는다. 실제 허용 기간은 여전히 오늘~다음 달 말일까지이며 62개라는 상한이 기간 밖 입력을 허용하는 것은 아니다. 큰 범위 입력에 따른 과도한 메모리/반복 처리를 예방하며 기존 저장 형식과 데이터를 바꾸지 않는다.

## D29. 저장 안내와 백업·복원 (H33, 2026-11-12)

이전에는 자동 저장 파일에 의존했다. 이제 설정에 백업·복원·지금 저장을 모으고 하단에 성공 시각과 실패 색상을 표시한다. 자동 저장은 유지하며 실패 시 현재 메모리 내용을 남겨 재시도할 수 있게 한다.

백업은 현재 메모리 상태 전체를 새 파일로 내보내고 기존 백업 덮어쓰기는 거절한다. 복원은 파일을 별도 객체로 검증한 뒤 현재 미저장 내용도 UUID 이름의 복구 파일로 저장하고 현재 파일을 교체한다. 성공 시 새 창을 열어 이전 서비스 참조와 응답 되돌리기를 제거한다. v1/v2 읽기 호환과 v3 저장은 유지한다. 사용 중인 파일 자체는 복원 대상으로 거절한다.

복구 파일이 쌓이고 동기 작업으로 큰 파일에서 지연될 수 있다. 다중 파일 트랜잭션·동시 실행 잠금·디스크 장애 복구를 보장하지 않는다. 일반/샘플 백업도 내용 구분 없이 복원하므로 파일 확인이 필요하다. 기존 데이터는 실제 사용자 파일을 변경하지 않고 임시 파일로 검사했다.

## D30. 제출 실행 환경과 명시적 저장 (H34, 2026-11-13)

지금 저장은 포커스 이동에 따른 자동 편집 종료에 의존하지 않고 직접 finishEditing 후 저장한다. 추가 컴포넌트 검사에서 편집 중 사유가 파일에 반영되지 않는 실패를 확인했기 때문이다. 자동 저장/데이터 형식은 유지한다. 빌드에는 --release 17을 명시해 더 높은 JDK에서 컴파일해도 최소 실행 환경 Java 17과 일치시킨다. 문서의 최신 검사 수는 377로 통일하고 과거 수치는 당시 기록으로 구분한다. 실제 다른 PC나 네이티브 전체 시연까지 완료했다는 뜻은 아니다.

## 현재 기능을 넘어가지 않은 범위

멤버 N명, 같은 파트 여러 명, 로그인·공유 투표, 기획 회차, 클라우드 동기화, iOS/Android 앱은 구현하지 않았다. 모바일 앱 요청은 사용자가 철회했다. 현재 6파트 고정·로컬 담당자 입력·합주 시간 20:00~22:00·최종 수동 확정은 그대로다.
