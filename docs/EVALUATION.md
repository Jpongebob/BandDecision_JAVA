# BandDecision 개발 문서 — 평가 기준별 정리

제출용으로 현재 구현과 최신 검사 결과를 압축한 문서는 [DEVELOPMENT_REPORT.md](DEVELOPMENT_REPORT.md)와 [PDF](BandDecision_Development_Report.pdf)다. 이 파일은 세부 평가 근거와 이전 작업 이력을 보존한다.

H46 UI 자기 점검과 사용자 요청: 일괄 적용 버튼 위에 대상 멤버·날짜 수를 보이고 직접 편집의 하루 범위를 구분했다. 변경 시 자동 저장과 실패 시 재시도, 오늘~다음 달 말일 전체 기준의 응답 완료 여부를 화면에 명시했다. 달력 요일·날짜·상태 글씨를 검정으로 그린다. 최신 자동 검사 170+198=368개와 Swing 렌더링을 확인했고 실제 마우스 전체 시연은 미실행이다. D41/V-20261119-01 참고.

H45 사용자 위치 피드백: 입력 멤버 선택기를 BAND DECISION 로고와 일정 메뉴 사이로 옮겼다. 기존 일정·투표 공유 선택기는 유지하며 배치·공유 검사와 렌더 화면에서 확인했다. V-20261118-10의 최신 자동 검사 170+197=367개 통과.

H44 재점검: 지난 날짜 숫자의 낮은 대비를 수정하고 170+197=367개 자동 검사와 렌더링을 확인했다. 설정 표 첫 열도 이름·파트 표시와 일치시켰다. Windows UI 조작 도구 연결 실패로 멤버·장소 대화상자의 실제 마우스 시연은 미완료이며 V-20261118-09/I02에 기록했다.

H42/H43 당시 확장: 기본 6명에서 최대 64명으로 멤버를 추가하고 이름·파트·실력을 수정할 수 있다. 같은 파트 여러 명과 인원별 응답·난이도·투표를 저장한다. 추천곡 찬성 기준은 전원 투표·인원의 2/3 이상이다. 확정 계획에는 장소를 입력·수정할 수 있고 예정/이전 내역을 나눠 본다. 이전 본문의 ‘고정 6명’은 당시 구현 기준의 이력이며 현재 동작은 D37/D38·V-20261118-07/08을 따른다. 당시 자동 검사 170+197=367개 통과.

확장 가능성: 멤버 삭제·순서 변경은 기존 일정·투표 인덱스 변환이 필요해 미구현이다. 처음부터 6명 미만으로 시작하는 설정, 합주 시간 수정, 장소 지도 연결, 온라인 동시 사용도 미구현이다. 현재 저장은 로컬 파일이며 사용자가 직접 조작하는 전체 시연은 별도 확인이 필요하다. 자세한 범위와 근거는 [개발 보고서](../DEVELOPMENT.md)의 ‘현재 확장 가능성과 남은 작업’을 따른다.

## 1. 문제, 사용자, 시나리오 정의 — 15%

### 누구의 어떤 문제인가

대상은 처음에 남성 보컬·여성 보컬·기타·베이스·드럼·건반 6명으로 시작하고 멤버를 추가할 수 있는 밴드다. 주 사용자는 멤버의 일정과 곡 의견을 모아 합주를 정하는 담당자이고, 정보 제공자는 각 멤버다. 현재 프로그램은 담당자가 한 PC에서 멤버별 응답을 입력하는 방식이며 멤버 각자의 온라인 로그인·동시 접속 기능은 없다.

사용자는 전원이 겹치는 날이 적고 콘솔의 날짜·메뉴를 한눈에 보기 어렵다고 설명했다. 이때 다음 세 가지 문제가 생긴다.

1. 날짜를 나열해서 비교하면 가능 인원과 미응답을 구별하기 어렵고, 응답이 없는 날을 가능으로 잘못 판단할 수 있다.
2. 좋아하는 곡이어도 특정 파트의 난이도가 현재 실력보다 높을 수 있다. 찬성 수만으로는 연주 부담을 설명하기 어렵다.
3. 결정 후에도 일정·투표가 바뀌므로 확정한 내용이 무엇이었는지 남겨야 한다. 재실행할 때 입력이 사라지거나 새 계획이 이전 계획을 덮으면 다시 확인해야 한다.

해결 목표는 **달력에서 명시적 응답을 모으고, 참석 인원과 연주 부담을 근거로 선택지를 제시한 뒤 담당자가 확정·보관하도록 돕는 것**이다. 전원 참석이 어려운 경우에도 불참 파트·사유를 보고 부분 참석을 판단하게 한다. 자동으로 최종 결정을 내리지 않는다.

핵심 저장 구조는 배열이다. 날짜 배열과 같은 인덱스의 `int[날짜 수][멤버 수]` 응답·`String[날짜 수][멤버 수]` 사유를 대응시킨다. 응답은 0=미응답, 1=가능, 2=불가다. 곡은 멤버별 난이도/투표/사유를 보관하고, 계획은 `ConfirmedPlan[]`으로 최대 5개다. 곡·계획 ID는 목록 위치와 구분하며 삭제 후에도 재사용하지 않도록 다음 ID를 저장한다.

### 계산 규칙

- 날짜: 해당 날짜 전원 응답 완료 → 가능 인원 1명 이상 → 가능 인원 내림차순, 같은 인원이면 빠른 날짜순.
- 파트 부담: `max(0, 곡 난이도 - 멤버 실력)`.
- 곡 점수: `3 × 찬성 수 - 2 × 총 파트 부담`.
- 곡 정렬: 점수 내림차순 → 찬성 수 내림차순 → 부담 오름차순 → 곡 ID 오름차순. 소스의 버블 정렬 비교 조건과 같다.
- 일정 응답 요약: 선택 멤버가 오늘~다음 달 말일의 미기록일 포함 모든 날짜에 응답했는지 표시한다. 이름과 기간을 명시하며 타인의 응답에 기준이 달라지지 않는다. 미기록 날짜를 가능으로 세지 않고 추천은 별도로 날짜별 현재 멤버 전원 응답을 검사한다.

### 데이터 및 실행 흐름

```text
스크립트 → 컴파일 → Main → DataStore.load 또는 새 상태/샘플 → GUI
날짜 선택 → respond/respondMany → 메모리 변경 → 화면/추천 갱신 → save
날짜·곡 선택 → preview → 부분 참석 동의·최종 확인 → confirm/updatePlan 재검증
→ 독립 스냅샷 추가/교체 → save → 목록에서 과거 내용 조회
```

다중 응답·곡 수정은 전체 입력을 검증한 뒤 반영한다. 저장은 임시 파일을 쓴 뒤 원본 파일을 교체하며, v1/v2는 최초 저장 전 버전별 백업을 만든다. 읽기는 새 객체에 검증하며 손상 파일은 덮어쓰지 않는다. 저장 실패 시 현재 메모리 변경은 남고 UI에 오류를 알린다. 파일의 `candidate.*` 이름은 기존 형식 호환용 키이며 후보 등록 UI가 있다는 뜻은 아니다.

## 6. 실행 및 사용 안내 — 10%

Windows PowerShell과 **JDK 17 이상**이 필요하다. `java -version`, `javac -version`이 모두 동작해야 한다. 외부 라이브러리·DB 설치는 없다. 제공할 자료에는 `src`, `test`, 실행/빌드 스크립트와 이 문서·README·docs를 포함한다. `out`은 스크립트가 만든다. 개인 일정이 든 `data`를 제출용 예시로 배포할 필요는 없다.

```powershell
cd D:\UNIV\2-2\JAVA\Project\BandDecision
.\run-gui.ps1 -Demo  # 별도 샘플 파일로 시연
```

그 밖에는 목적에 맞는 명령 하나를 선택한다.

| 목적 | 명령 |
|---|---|
| 일반 저장 파일로 GUI 실행 | `.\run-gui.ps1` |
| GUI 실행(동일 기능) | `.\run.ps1` |
| 자동 검사 | `.\build.ps1 -Test` |

프로젝트를 다른 위치에 풀었으면 첫 줄만 실제 프로젝트 폴더 경로로 바꾼다. `Project`가 아니라 실행 스크립트가 있는 `BandDecision` 폴더에서 실행한다. PowerShell 정책이 막으면 `powershell -NoProfile -ExecutionPolicy Bypass -File .\run-gui.ps1 -Demo`처럼 해당 실행에 옵션을 지정할 수 있다.

사용 순서: 사이드바의 입력 멤버 확인 → 일정에서 하루/기간/월 전체 응답 → 곡·투표에서 목록 선택·난이도 확인·내 투표 저장 → 합주 계획의 새 합주 만들기에서 날짜·곡 선택 → 부분 참석/최종 확인 → 같은 메뉴의 확정된 계획에서 조회·수정·삭제. 실력은 밴드 설정, 난이도는 선택 곡 수정창에서 관리한다. 여러 추천곡은 Ctrl/Shift로 선택한다.

일반 데이터는 `data/banddecision.properties`, 샘플은 `data/demo.properties`에 저장하며 한 번에 하나의 프로그램만 실행한다. 샘플도 재실행 시 이어지므로 오래된 샘플 날짜가 과거이면 오늘 이후 날짜의 응답을 추가해서 시연한다. 파일 오류 안내가 나오면 원본을 덮어쓰지 않고 종료하며, 저장 실패 상태에서는 메모리 변경이 남을 수 있으므로 안내를 확인한다. v3 파일은 구버전 프로그램에서 읽을 수 없다.

자세한 화면별 사용법·직접 Java 실행과 인코딩 안내는 [README](../README.md)에 있다. 새 폴더·다른 PC에서 다른 사람이 실제 실행하는 인수 시연과 학생 본인의 설명 확인은 아직 미완료다.

2026-11-19 사용자 전달 안내: 구현과 시연은 `-Demo` 화면으로 충분하다. 기능을 처음부터 모두 다시 입력하는 시연은 요구하지 않으며, 발표에서는 그 샘플로 연결된 동작과 설계 이유를 설명한다. 발표자료 PDF와 실제 시간 측정·동료 검토·본인 직접 시연 완료 여부는 별도로 기록한다.
