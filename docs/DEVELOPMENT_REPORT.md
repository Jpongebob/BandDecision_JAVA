# BandDecision 개발 문서

작성 기준: 2026-11-19 · 대상: Java 17 Swing 데스크톱 앱 · 실행 방식: `-Demo`로 발표 시연

이 문서는 `2026-2 Java 12주차.pdf` 9쪽의 개발 문서 평가 6항목 순서로 현재 구현을 설명한다. 11주차 강의자료의 기능 연결·수정 기록 요구도 반영했다. 사용자 요구와 수업 자료는 구분한다. 자동 검사는 개발 지원 도구가 실행했으며 학생 본인의 직접 시연이나 동료 평가로 적지 않는다. 상세 변경 이력은 [CHANGELOG](CHANGELOG.md), 판단 이유는 [DECISIONS](DECISIONS.md), 명령과 출력은 [VERIFICATION](VERIFICATION.md)에 있다.

## 1. 문제, 사용자, 시나리오 정의 — 15%

**대상 사용자**는 밴드의 합주 날짜와 곡을 정리하는 담당자다. 멤버는 자신의 날짜별 가능 여부와 곡에 대한 찬반·난이도 정보를 제공한다. 현재 앱은 담당자가 한 PC에서 멤버를 선택해 대신 입력하는 로컬 프로그램이며, 멤버별 로그인이나 동시 접속은 제공하지 않는다. 기본 6명으로 시작하지만 최대 64명까지 추가할 수 있고 같은 파트를 여러 명이 맡을 수 있다.

**문제**는 전원이 겹치는 합주 날짜가 적어서 불참 인원과 미응답을 구분해야 하고, 후보곡은 단순 찬성 수뿐 아니라 멤버의 실력 대비 연주 난이도도 고려해야 한다는 것이다. 결정 뒤 응답·투표가 바뀌어도 당시 확정한 날짜·참석자·곡을 확인할 수 있어야 한다. 콘솔의 긴 메뉴와 날짜 목록은 이 비교를 어렵게 했다.

**목표**는 날짜별 명시적 응답과 곡별 투표를 모아 근거 있는 추천을 제시하고, 담당자가 부분 참석 여부까지 확인해 합주 계획을 직접 확정·보관하도록 돕는 것이다. 프로그램은 최종 결정을 자동으로 내리지 않는다.

| 대표 시나리오 | 사용자 행동 | 확인 가능한 결과 |
|---|---|---|
| S1 날짜 찾기 | 사이드바에서 멤버를 고르고 달력에서 하루·기간·월 전체를 선택해 가능/불가를 적용한다. | 선택한 멤버·날짜만 바뀐다. 미응답은 가능으로 추정하지 않는다. 날짜별 전원 응답 후 가능 인원이 많은 날짜를 추천한다. |
| S2 곡 결정 | 제목·아티스트·멤버별 난이도를 등록하고 멤버별 찬반과 반대 사유를 입력한다. | 투표 현황을 곡 옆에서 보고, 전원 투표와 찬성 기준을 만족한 곡을 부담을 반영한 점수로 비교한다. |
| S3 합주 확정 | 추천 날짜·곡을 선택하고 장소를 입력한다. 부분 참석 경고와 최종 내용을 확인한다. | 최대 5개 계획을 저장하고 달력에서 확정 날짜를 구분한다. 이전/예정 내역을 조회·수정·삭제한다. |
| S4 다음 실행 | 프로그램을 닫고 같은 모드로 다시 실행한다. | 일반 데이터와 Demo 데이터를 별도 파일에서 읽고 기존 응답·투표·계획을 복원한다. |

## 3. 프로그램 설계 — 20%

| 구성요소 | 책임과 관계 |
|---|---|
| `Main`·실행 스크립트 | 일반/`-Demo` 모드와 파일 경로를 고르고 저장 파일을 읽거나 첫 데이터를 만든 뒤 Swing 창을 시작한다. |
| `DesktopUI`·`WorkspaceView`·`ScheduleCalendarPanel` | 메뉴, 공통 멤버 선택, 달력·표·입력·확인창을 담당한다. 입력 결과는 서비스에 전달하고 변경 뒤 화면을 갱신·저장한다. |
| `BandDecision` | 멤버·일정·곡·확정 계획을 보관한다. `preview`로 확정 후보를 만들고 `confirm/updatePlan`에서 최신 정보와 사용자 동의를 다시 검증한다. |
| `AttendanceService`·`ScheduleWindow`·`DateRecommender` | 날짜별 응답·사유와 오늘~다음 달 말일 범위를 관리한다. 전원 응답한 날짜를 참석 인원순으로 추천한다. |
| `Song`·`SongService`·`SongRecommender` | 곡·난이도·찬반·사유를 관리하고 자격과 부담 점수로 곡을 추천한다. |
| `ConfirmedPlan`·`RehearsalPlan` | 계획 ID와 확정 당시 참석/불참·사유·곡·장소의 독립 복사본을 보관한다. 현재 응답이 바뀌어도 과거 내용은 자동으로 바뀌지 않는다. |
| `DataStore` | Properties 형식의 UTF-8 저장·복원, 임시 파일 작성 후 교체, 옛 버전 읽기와 최초 전환 시 원본 보존을 담당한다. |

**데이터 관계.** 멤버 배열은 현재 순서를 유지한다. 날짜 배열의 각 날짜에 같은 멤버 인덱스의 응답·사유 배열이 대응한다. 곡은 ID, 멤버별 난이도·투표·사유 배열을 갖는다. 새 멤버가 들어오면 일정과 곡 배열도 함께 확장한다. 확정 계획은 최대 5개 배열이고 내부 ID는 삭제 후 재사용하지 않는다. 곡 ID는 화면에서 숨기지만 저장·선택 연결에는 사용한다. 파일의 `candidate.*` 키는 옛 버전과 호환하기 위한 이름이며 후보 날짜 사전 등록 UI가 있다는 뜻이 아니다.

**실행 흐름.**

```text
run-gui.ps1 -Demo → build.ps1 → Main → DataStore.load 또는 DemoData 생성
→ DesktopUI / WorkspaceView
→ 날짜 응답 → AttendanceService → DateRecommender → 화면 갱신 → DataStore.save
→ 곡 등록·투표 → SongService / SongRecommender → 화면 갱신 → save
→ 날짜·곡·장소 선택 → BandDecision.preview → 부분 참석·최종 확인
→ BandDecision.confirm 또는 updatePlan 재검증 → 확정 스냅샷 → save
```

선택 멤버의 ‘응답 완료’는 기간 전체 모든 날짜에 답했는지를 뜻한다. 날짜 추천은 **그 날짜의 전원 응답**을 기준으로 하므로 두 상태를 구분한다. GUI에서 날짜를 선택하는 것만으로 응답이 바뀌지 않고 적용 버튼을 눌러야 한다. 오른쪽 응답표를 직접 편집하면 표시한 하루만 바뀐다.

## 5. 테스트 조건, 문제, 수정과 재시험 — 20%

**이번 확인 환경과 결과(2026-11-19).** Windows PowerShell, Temurin OpenJDK/Javac 17.0.20.1에서 `powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test`를 실행했다. 출력은 `PASS: 170 checks (scheduling + songs + persistence)`와 `PASS: 198 Swing checks`, 합계 **368개**, 종료 코드 0이었다. 이어 `java -Dfile.encoding=UTF-8 -cp out GuiSmokeTest --render`를 실행해 `PASS: 198 Swing checks`, 종료 코드 0을 얻었다. 렌더 검사의 198개는 368개에 다시 더하지 않는다. 검사는 별도 임시 데이터로 수행했고 사용자 `data/`를 변경하지 않았다.

| 조건 | 기대 결과 | 실제 결과와 근거 |

**실패에서 개선까지의 기록.** 멤버 추가 작업 중 GUI 선택기를 다시 채울 때 선택 인덱스가 잠시 -1이 되어 예외가 난 것을 자동 검사에서 발견했다. 멤버 배열을 먼저 갱신하고 -1 이벤트를 무시하도록 고친 뒤 7명 일정·곡·투표·저장 검사를 다시 통과했다(V-20261118-07). 달력의 지난 날짜 숫자가 흐린 것을 렌더 검토에서 발견해 검정으로 바꾸고 비활성화 정책은 유지한 채 367개 검사와 렌더를 재실행했다(V-20261118-09). 이번에는 적용 대상 안내를 버튼 위로 옮기고 상태 글씨를 검정으로 바꿔 368개 검사와 렌더를 재실행했다(V-20261119-01). 중간의 컴파일 괄호 오류도 수정 후 재빌드했다.

**검증 한계.** Swing 자동 검사·이미지 렌더는 실제 마우스로 모든 확인창을 통과한 시험이 아니다. 학생 본인의 직접 시연, 동료 검토, 다른 PC/DPI 시험, 권한 부족·디스크 부족 오류 주입은 미완료다. 저장 파일을 여러 창에서 동시에 수정하면 마지막 저장이 이전 변경을 덮을 수 있어 한 번에 한 창만 실행하도록 안내한다. 남은 내용은 [ISSUES](ISSUES.md)에 적었다.

## 6. 실행 및 사용 안내 — 10%

Windows PowerShell과 JDK 17 이상(`java`, `javac`)이 필요하며 외부 라이브러리나 DB 설치는 없다. 실행 스크립트가 있는 `BandDecision` 폴더에서 다음을 실행한다.

```powershell
java -version
javac -version
.\build.ps1 -Test
.\run-gui.ps1 -Demo
```

PowerShell 실행 정책이 스크립트를 막으면 `powershell -NoProfile -ExecutionPolicy Bypass -File .\run-gui.ps1 -Demo`를 사용한다. `run.ps1 -Demo`도 같은 GUI이고, 인자 없이 실행하면 일반 데이터 파일을 사용한다. 발표는 사용자 전달 안내에 따라 **기존 Demo 데이터로 시연**한다. 처음 실행은 가상의 8곡·2계획을 만들고 다음 실행부터 `data/demo.properties`를 다시 읽으므로 입력이 초기화되지 않는다. 날짜가 지나 오래된 Demo의 유효 날짜가 부족하면 원본 파일을 지우지 말고 개인 데이터가 없는 새 복사본에서 Demo를 생성해 시연한다.

시연 순서는 사이드바에서 입력 멤버 확인 → 달력의 날짜별 응답·추천 → 곡별 찬반·난이도·추천 → 합주 계획의 장소·참석자·선정곡·달력 표시다. 필요하면 가상 데이터의 응답 한 건을 바꿔 자동 저장과 추천 갱신을 보여준다. 화면에서 직접 편집하는 방법은 [README](../README.md)와 [USAGE](USAGE.md)에 있다. 일반 저장은 `data/banddecision.properties`이고 Demo 저장과 분리된다. 사용자 개인 `data/`는 제출용 예시로 배포하지 않는다.
