## 2026-11-11 작업군: 날짜 결정 정책 변경

### H15. 후보 날짜와 가능 여부 응답 방식 채택

- 계기: 사용자 밴드는 전원이 겹치는 날이 적고 60일 전체의 불가능 일정을 입력하는 방식이 실제 결정에 불편했다.
- 선택: 담당자가 후보 5~10개 정도를 제시하고, 각 멤버가 후보별 가능/불가를 명시. 미응답은 가능으로 간주하지 않는다.
- 변경: `AttendanceService`, `DateRecommender`, `BandDecision`, `DesktopUI`, `ConsoleUI`, `DemoData`, `DataStore`, 검사와 사용 문서.
- 상태: 현재 채택된 방식. 유효 후보는 오늘~59일 뒤, 개수는 강제하지 않는다.
- 추천: 유효한 모든 후보에 6명 전원 응답 후 가능 인원 내림차순·날짜 오름차순. 전원 불가 및 등록하지 않은 날짜 제외.
- 데이터: v2로 후보·응답 저장. v1은 `.v1.bak` 백업, 곡·투표·실력·확정 보존. 일반 데이터의 가능 여부는 추정하지 않고 새로 응답한다.
- 당시 확인: 도메인·콘솔·파일 검사 96개, GUI 검사 26개 통과. 후보 표와 추천 화면 렌더링 확인.
- 주의: 구방식의 `없음` 제출·자동 60일 전수 탐색은 현재 기능으로 홍보하지 않는다. 모바일/N명 프로젝트는 잘못 보낸 요청으로 철회됐으며 구현하지 않았다.
