# BandDecision

밴드 멤버의 합주 가능 날짜와 후보곡 투표를 모아 합주를 추천하고, 밴드장이 최종 계획을 확정하는 **Java Swing 데스크톱 앱**입니다. 일정·곡·투표·확정 계획을 한 화면의 메뉴에서 관리합니다. 처음에는 6명이 등록되며 멤버를 추가하거나 이름·파트·실력을 바꿀 수 있습니다. 같은 파트를 여러 명이 맡아도 됩니다.

## 실행 준비

- Windows PowerShell과 **JDK 17 이상**이 필요합니다. `java`와 `javac`가 모두 명령줄에서 실행되어야 합니다.
- 외부 Java 라이브러리나 별도 설치 프로그램은 필요하지 않습니다.
- 명령은 **`run-gui.ps1`이 있는 프로젝트 폴더**에서 실행합니다. GitHub에서 새로 받았다면:

```powershell
git clone https://github.com/Jpongebob/BandDecision_JAVA.git
cd BandDecision_JAVA
java -version
javac -version
.\run-gui.ps1 -Demo
```

이미 프로젝트를 받았다면 해당 폴더에서 `.\run-gui.ps1`을 실행하세요. PowerShell 실행 정책으로 스크립트가 막히면 해당 실행에만 다음 명령을 사용합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-gui.ps1 -Demo
```

| 실행 | 용도 | 저장 파일 |
| --- | --- | --- |
| `.\run-gui.ps1 -Demo` | 2026-12-09 기준 발표용 가상 데이터 | `data/demo-2026-12-09.properties` |
| `.\run-gui.ps1` | 기본 멤버 6명에서 일정·곡을 직접 입력 | `data/banddecision.properties` |
| `.\build.ps1 -Test` | 컴파일과 자동 검사 | 사용자 데이터 사용 안 함 |

`.\run.ps1`과 `.\run.ps1 -Demo`도 각각 같은 GUI를 엽니다. 콘솔 메뉴는 없습니다. IntelliJ에서 실행할 때는 JDK 17 이상으로 `Main`을 실행하고, Demo에는 프로그램 인수 `--demo`를 지정합니다.

### Demo로 빠르게 살펴보기

**Demo의 오늘은 2026년 12월 9일로 고정**됩니다. 달력·응답 완료·날짜 추천·지난 날짜·계획의 예정/이전 분류가 모두 같은 기준을 사용하고, 달력은 2026년 12월과 2027년 1월을 보여줍니다. 일반 실행은 실제 날짜를 사용합니다.

현재 공유된 발표용 파일은 사용자가 기존 Demo에 직접 입력한 데이터(멤버 6명, 곡 4개, 확정 계획 5개, 기록 날짜 44개)를 사용합니다. 곡·투표·응답·사유·계획 날짜를 그대로 보존했으므로 12월 9일 전의 계획은 이전 내역으로 표시됩니다.

발표용 파일이 없을 때만 2026-12-09~2027-01-31의 가상 일정, 후보곡 8개, 확정 계획 2개를 만듭니다. 다시 실행하면 `data/demo-2026-12-09.properties`의 수정 내용을 유지합니다. 예전 `data/demo.properties`와 일반 데이터는 덮어쓰지 않으며, 예전 Demo 입력이 새 발표용 파일로 자동 이전되지는 않습니다. 새 예시로 시작하려면 발표용 파일을 다른 이름으로 보관한 뒤 다시 실행합니다.

시연할 때는 사이드바 멤버를 바꿔 달력 응답을 비교하고, **곡·투표**에서 후보곡별 찬반을 확인한 다음 **합주 계획**에서 추천 날짜·곡과 확정 계획을 보여주면 됩니다.

## 화면 사용법

입력 항목의 `*`는 필수, `(선택)`은 비워도 되는 항목입니다. 합주 장소와 일정 불가 사유는 선택 입력입니다. 멤버 이름은 추가할 때 필수이고 수정할 때는 선택이며, 비우면 파트만 표시합니다. 반대 투표의 사유는 반대할 때만 필수입니다.

왼쪽 **BAND DECISION** 로고와 **일정** 메뉴 사이에서 입력할 멤버를 선택합니다. 이 멤버 선택은 일정과 곡 투표에 공통으로 적용됩니다.

### 1. 일정

- 달력은 **오늘부터 다음 달 말일**까지 응답할 수 있습니다. 날짜를 누르면 하루가 선택됩니다. 여러 날은 **기간으로**에서 시작일·종료일을 누르거나 **이 달 전체**를 누릅니다. 월 전체를 다시 누르면 선택이 해제됩니다. 지난 날짜는 편집할 수 없습니다.
- 선택만으로 응답이 저장되지는 않습니다. 적용 버튼 위의 **멤버와 날짜 수**를 확인하고 **가능 적용 / 불가 적용 / 미응답 적용**을 누릅니다. 오른쪽 응답표에서 직접 수정하면 표시 중인 **하루만** 바뀝니다. 불가 사유는 선택 입력입니다.
- **응답 완료**는 선택한 멤버가 오늘~다음 달 말일의 모든 날짜에 가능 또는 불가로 답했는지 나타냅니다. 날짜 추천은 **그 날짜의 모든 멤버가 응답**하면 계산합니다. 다른 날짜에 미응답이 있어도 해당 날짜의 추천은 막히지 않습니다.
- 달력 범례의 **가능(파랑) / 불가(빨강)**는 현재 선택한 멤버의 응답입니다. 전원 가능은 **초록**, 확정 합주는 **보라**로 표시합니다. 선택 범위는 테두리·체크로 구분합니다. **합주 가능**은 날짜 응답 결과이고 **합주 확정**은 확정 계획입니다.
- **마지막 응답 되돌리기**는 이번 실행 중 마지막 일정 변경 한 건을 복원하고 저장합니다.

### 2. 곡·투표

- 곡별 난이도는 **0~5**입니다. **0은 ‘연주 안 함’**으로 표시하며 해당 곡의 연주 부담을 0으로 계산합니다. 예를 들어 여성 보컬만 부르는 곡은 남성 보컬 난이도를 0으로 둘 수 있습니다. 멤버 실력은 계속 1~5입니다.
- 연주하지 않는 멤버도 밴드의 곡 선정 투표에는 참여합니다. 전원 투표·전체 멤버의 2/3 이상 찬성 기준은 유지하며, 모든 멤버의 난이도가 0인 곡은 추천하지 않습니다.

- 후보곡을 등록·수정·삭제하고 곡 목록에서 찬성·반대·미응답 수를 확인합니다. 곡을 선택하면 멤버별 난이도와 투표가 표시됩니다.
- 사이드바에서 투표할 멤버를 고른 뒤 찬성 또는 반대에 응답하고 **내 투표 저장**을 누릅니다. 반대할 때는 사유가 필수입니다.
- 곡 수정은 기존 투표를 유지합니다. 곡 삭제는 해당 곡의 투표도 지우지만 이미 확정된 계획의 기록은 유지합니다. 곡의 내부 ID는 화면에 표시하지 않습니다.

### 3. 합주 계획

- **새 합주 만들기**에서 추천 날짜 1개와 추천곡 1개 이상을 고릅니다. 곡은 왼쪽 **선택 체크박스**를 눌러 여러 개 고르고, 다시 누르면 해제합니다. 아래에 선택한 곡 수가 표시됩니다. 장소를 입력하지 않으면 **미정**으로 표시합니다.
- 이미 합주가 확정된 날짜는 새 합주 추천에서 제외합니다. 계획 수정 시에는 수정 중인 계획의 날짜를 유지하고 다른 계획의 날짜는 제외합니다. 계획을 삭제하면 그 날짜는 응답 조건을 충족하는 경우 다시 추천됩니다.
- 부분 참석 경고와 최종 내용을 확인한 뒤 확정합니다. 계획은 **최대 10개**이며 **확정된 계획** 목록에서 예정된 계획과 이전 내역을 조회하고 수정·삭제할 수 있습니다. 목록은 날짜가 빠른 순으로 정렬하며 계획 ID는 표시하지 않습니다.
- 확정 날짜는 달력에 보라색으로 표시됩니다. 계획을 수정·삭제하면 달력 표시도 갱신됩니다. 확정 뒤 원래 응답이나 후보곡을 바꿔도 이미 확정한 계획은 자동으로 바뀌지 않습니다.

### 4. 밴드 설정

멤버 이름·파트·실력을 수정하거나 멤버를 추가·삭제합니다(**1~12명**). 처음에는 6명이지만 불필요한 기본 멤버를 삭제해 1~5명 밴드로 운영할 수 있습니다. 같은 파트도 여러 명이 맡을 수 있습니다. 추가 멤버는 기존 날짜·곡에서 미응답으로 시작하고, 기존 곡 난이도는 기본 3입니다. 삭제 전 확인창을 보여주며 해당 멤버의 날짜 응답·곡 난이도·투표가 함께 삭제됩니다. 이미 확정된 계획의 당시 참석·불참 기록은 보존합니다. 마지막 1명은 삭제할 수 없습니다. 변경은 자동 저장되고 실패하면 **저장 다시 시도**를 누릅니다. 순서 변경과 수동 백업·복원 메뉴는 없습니다.

## 추천 기준

- 날짜: 해당 날짜 **전원 응답** 및 **가능 인원 1명 이상**일 때 추천합니다. 가능 인원이 많은 순, 같은 수면 빠른 날짜 순입니다. 부분 참석 날짜도 최종 확인을 거쳐 확정할 수 있습니다.
- 곡: **전원 투표**하고 **전체 멤버의 2/3 이상 찬성**해야 추천합니다. 예를 들어 6명이면 4명, 7명이면 5명 이상입니다. 부담은 `max(0, 난이도 - 멤버 실력)`, 점수는 `3 × 찬성 수 - 2 × 총 부담`입니다.

## 저장과 확인

데이터는 프로젝트의 `data/`에 UTF-8 파일로 자동 저장되고 재실행 시 복원됩니다. Demo와 일반 데이터는 별도 파일입니다. **공유용 `data/demo-2026-12-09.properties`와 예전 `data/demo.properties`만 Git에 포함**하며 일반 데이터·백업과 컴파일 결과 `out/`은 제외합니다. Demo의 새 입력은 발표용 파일에 저장되고 커밋·푸시 후 GitHub에 반영됩니다. 앱 저장 자체가 자동 커밋·푸시를 실행하지는 않습니다. **같은 데이터 파일을 두 창에서 동시에 편집하지 마세요.** 이전 저장 형식(v1/v2)은 읽을 수 있으며 변환 전 원본을 보관하고 새 저장은 v3 형식으로 합니다.

```powershell
.\build.ps1 -Test
```

2026-11-21에 개발 지원 도구가 실제 실행한 자동 검사는 **기능 206개 + Swing 233개**, 종료 코드 0이었습니다. 곡 체크 선택, 확정 날짜 제외, 계획 날짜순 정렬·ID 숨김, 10개 저장과 11번째 거부, 12명 운영과 13번째 멤버 거부를 포함합니다. 네이티브 창의 전체 마우스 시연과 다른 PC에서의 실행은 별도로 확인해야 합니다. 상세 조건·결과는 로컬 `docs/VERIFICATION.md`에 있습니다.
